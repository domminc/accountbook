# 가계부 사이트 기획서

> 상태: 초안 (v0.1) · 작성일: 2026-09-25
>
> ⚠️ 참고 시트 링크가 아직 전달되지 않아, 이 초안은 일반적인 가계부 스프레드시트 구조를 기준으로 작성했습니다.
> 시트를 받으면 [6. 참고 시트 매핑](#6-참고-시트-매핑)을 채우고 카테고리·화면 구성을 시트에 맞게 조정합니다.

---

## 1. 개요

스프레드시트로 관리하던 가계부를 웹으로 옮겨, **입력은 더 빠르게, 집계는 자동으로, 가족과 함께** 볼 수 있도록 한다.

### 목표
- 거래 1건 입력을 **10초 안에** 끝낸다 (모바일 기준).
- 월별 수입·지출·예산 대비 실적을 **따로 계산하지 않아도** 바로 보여준다.
- 기존 시트 데이터를 **그대로 가져와** 이어서 쓸 수 있다.
- 부부·가족이 **하나의 가계부를 함께** 쓴다.

### 하지 않을 것 (v1 범위 밖)
- 은행·카드사 자동 연동 (오픈뱅킹, 마이데이터)
- 투자 수익률 계산, 세금 신고 지원
- 네이티브 앱 (모바일 웹 + PWA로 대체)

## 2. 대상 사용자

| 사용자 | 상황 | 핵심 니즈 |
|---|---|---|
| 기존 시트 사용자 (주 사용자) | 구글 시트/엑셀로 가계부를 쓰고 있음 | 데이터 이전, 시트보다 편한 입력, 자동 집계 |
| 공동 관리자 (배우자·가족) | 가끔 입력하고 주로 조회함 | 모바일에서 빠른 입력, 이번 달 현황 확인 |

## 3. 핵심 기능

### MVP (1차)
1. **거래 입력/수정/삭제**
   - 유형: 수입 / 지출 / 이체(계좌 간 이동: 수입·지출 집계에서 제외)
   - 필드: 날짜, 금액, 카테고리(대/소분류), 결제수단(계좌·카드·현금), 메모, 입력자
   - 최근 사용 카테고리·결제수단 자동 추천, 직전 입력값 복제
2. **거래 내역 조회**: 월 단위 리스트 뷰 + 달력 뷰, 카테고리·결제수단·입력자 필터, 메모 검색
3. **대시보드**: 이번 달 수입·지출·잔액, 예산 소진율, 카테고리별 지출 비중, 최근 거래
4. **월 예산**: 카테고리별 월 예산 설정, 예산 대비 실적(남은 금액, 초과 경고)
5. **카테고리·결제수단 관리**: 추가/수정/숨김, 정렬 순서
6. **시트 가져오기/내보내기**: CSV 업로드 → 컬럼 매핑 → 미리보기 → 저장. 전체 데이터 CSV 내보내기
7. **가구 공유**: 이메일 초대로 한 가계부를 함께 사용

### 2차
- **고정 지출/수입 반복 등록** (월세, 통신비, 보험료, 월급 등): 매월 자동 생성 또는 확인 후 생성
- **신용카드 청구월 기준 보기**: 사용일 기준과 결제일 기준 전환
- **할부** 입력 (총액·개월 수 입력 → 월별 분할)
- **통계 리포트**: 월별 추이, 카테고리별 전년 동월 비교, 연간 요약
- PWA (홈 화면 추가, 오프라인 입력 후 동기화)

### 3차 (검토)
- 영수증 사진 첨부
- 카드 문자·알림 붙여넣기로 자동 파싱
- 저축 목표(목표 금액·기한·달성률)

## 4. 화면 구성 (IA)

```
/                 대시보드
/transactions     거래 내역 (리스트 | 달력) + 빠른 입력
/budget           월 예산 설정 및 실적
/reports          통계 (2차)
/settings
  ├─ categories   카테고리 관리
  ├─ accounts     결제수단·계좌 관리
  ├─ members      가구 멤버 초대
  └─ data         가져오기 / 내보내기
```

### 주요 화면 요소

**대시보드**
- 상단 요약 카드 3개: 이번 달 수입 / 지출 / 잔액 (전월 대비 증감)
- 예산 진행 바: 전체 + 상위 카테고리별 (80% 주의, 100% 초과 색상 구분)
- 카테고리별 지출 비중 (가로 막대, 상위 5개 + 기타)
- 최근 거래 5건

**거래 내역**
- 상단: 월 이동(◀ 2026.09 ▶), 월 합계
- 리스트: 날짜별 그룹, 일별 소계
- 달력: 날짜 칸에 일 지출 합계, 클릭 시 해당일 거래
- 입력: 모바일은 하단 플로팅 `+` 버튼 → 바텀시트, 데스크톱은 표 상단 인라인 입력 행

**예산**
- 카테고리별 예산 / 실적 / 잔여 표
- "지난달 예산 복사" 버튼

## 5. 데이터 모델

금액은 **원 단위 정수**(`bigint`)로 저장한다. 소수점 계산 오차를 피하기 위해서다.

```
households        가구
  id, name, created_at

members           가구 구성원
  id, household_id, user_id, role(owner|member), display_name

accounts          결제수단·계좌
  id, household_id, name, type(bank|card|cash|etc), is_hidden, sort_order
  card_billing_day (카드 결제일, 2차)

categories        카테고리 (2단계)
  id, household_id, parent_id(null이면 대분류), type(income|expense),
  name, icon, color, is_hidden, sort_order

transactions      거래
  id, household_id, type(income|expense|transfer),
  occurred_on(date), amount(bigint, 항상 양수),
  category_id(이체는 null), account_id, to_account_id(이체만),
  memo, created_by, created_at, updated_at,
  recurring_rule_id(2차), import_batch_id

budgets           월 예산
  id, household_id, month(YYYY-MM), category_id, amount
  UNIQUE(household_id, month, category_id)

recurring_rules   반복 거래 (2차)
  id, household_id, template(거래 필드), day_of_month, start_month, end_month

import_batches    가져오기 이력 (되돌리기용)
  id, household_id, file_name, row_count, created_by, created_at
```

### 기본 카테고리 (시트 확인 후 교체)

| 유형 | 대분류 | 소분류 예시 |
|---|---|---|
| 지출 | 식비 | 장보기, 외식, 배달, 카페·간식 |
| 지출 | 주거·통신 | 월세·관리비, 전기·가스·수도, 인터넷·휴대폰 |
| 지출 | 생활 | 생필품, 가구·가전 |
| 지출 | 교통 | 대중교통, 주유, 주차·통행료, 택시 |
| 지출 | 의료·건강 | 병원, 약국, 운동 |
| 지출 | 교육·육아 | 학원, 교재, 육아용품 |
| 지출 | 문화·여가 | 구독, 여행, 취미 |
| 지출 | 의류·미용 | 의류, 미용실 |
| 지출 | 경조사·선물 | 경조사비, 선물, 용돈 |
| 지출 | 금융 | 보험, 대출이자, 수수료 |
| 수입 | 근로소득 | 월급, 상여 |

## 6. 참고 시트 매핑

> 시트 링크를 받으면 채울 부분입니다.

- [ ] 시트 탭 구성 (예: 월별 탭 / 연간 요약 / 카테고리 목록)
- [ ] 거래 입력 컬럼 → `transactions` 필드 매핑
- [ ] 시트의 카테고리 체계 → `categories` 초기 데이터
- [ ] 시트의 집계 수식·요약표 → 대시보드·리포트 항목
- [ ] 시트에만 있는 특수 항목 (예: 카드별 청구 금액, 고정지출 표, 저축 현황)
- [ ] 가져오기 시 날짜·금액 형식 (예: `2026. 9. 25`, `₩12,000`, 음수 지출 표기)

## 7. 기술 스택 (제안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript | 화면·API를 한 저장소에서 관리, Vercel 배포가 간단함 |
| UI | Tailwind CSS + shadcn/ui | 모바일 대응 폼·바텀시트·표를 빠르게 구성 |
| DB·인증 | Supabase (PostgreSQL + Auth) | 이메일/소셜 로그인, Row Level Security로 가구 단위 데이터 격리 |
| 차트 | Recharts | 도넛·막대·추이 차트에 충분함 |
| 폼·검증 | React Hook Form + Zod | 입력 폼과 CSV 가져오기 검증 스키마를 공유 |
| 배포 | Vercel + Supabase 무료 플랜 | 가족 규모 사용량은 무료 범위 안에 들어옴 |
| 테스트 | Vitest (집계 로직), Playwright (입력·가져오기 흐름) | |

**보안**: 모든 테이블에 `household_id` 기준 RLS를 적용해 본인이 속한 가구 데이터만 읽고 쓸 수 있게 한다.

## 8. 일정 (안)

| 단계 | 기간 | 산출물 |
|---|---|---|
| 0. 기획 확정 | 1주 | 참고 시트 매핑 완료, 화면 와이어프레임 |
| 1. 기반 | 1주 | 프로젝트 셋업, 인증, DB 스키마·RLS, 기본 카테고리 시드 |
| 2. 거래 | 2주 | 거래 입력/조회(리스트·달력), 카테고리·결제수단 관리 |
| 3. 집계 | 1주 | 대시보드, 월 예산 |
| 4. 데이터 이전 | 1주 | CSV 가져오기/내보내기, 실제 시트 데이터로 검증 |
| 5. 공유·마무리 | 1주 | 가구 초대, 모바일 다듬기, 배포 |

MVP까지 약 **7주**.

## 9. 결정이 필요한 사항

1. **참고 시트 링크** (카테고리·컬럼 구조 확정에 필요)
2. 사용 인원: 혼자 / 부부 / 가족 (공유 기능 우선순위가 달라짐)
3. 신용카드 지출 기준: 사용일 기준으로만 볼지, 청구월 기준 보기도 MVP에 넣을지
4. 로그인 방식: 이메일 / 카카오 / 구글
5. 기존 시트를 계속 병행할지, 이전 후 시트 사용을 끝낼지 (병행 시 주기적 가져오기 필요)
